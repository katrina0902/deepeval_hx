# 测试用例与样例池维护工作流

> 适用场景：当用户要求设计或维护某个 Prompt 的测试用例和具体测试样例池时使用。
>
> 本工作流负责测试目标、通过标准、覆盖方向及测试资产维护。应完整读取并遵循 `项目全局/第2层-具体规则层/测试用例设计规则.md` 和 `项目全局/第3层-任务流程层/prompt调试资产模板.md`。
>
> 更新本工作流时：只在测试资产的准备、维护或交付方式发生变化时修改；测试用例设计的通用判断在 `项目全局/第2层-具体规则层/测试用例设计规则.md` 中维护，目录、记录要求和工作簿结构在 `项目全局/第3层-任务流程层/prompt调试资产模板.md` 中维护。

## 1. 确认测试对象与维护范围

先确认用户指定的 Prompt、需求、已有测试资产和本次维护范围。已有测试用例、样例和通过标准仍然适用时，直接复用，只维护本次受影响的部分。

先读取需要调试的 prompt，摘出以下内容：

- 任务目标
- 输入边界
- 输出契约
- 关键判断规则
- 条件分支
- 异常处理要求

读取完 prompt 后，先检查任务目标、输入边界、输出契约、条件分支和异常处理是否足以支撑后续测试。如果发现缺失或歧义，应记录并提示人工决定是否修改 prompt、暂缓对应测试或排除该测试情形，不自动修改 prompt。人工决定修改时，再按 `项目全局/第2层-具体规则层/prompt撰写规则.md` 处理。

确认调试对象后，先定下本轮通过标准：哪些关键判断必须正确、哪些字段必须存在、稳定性要到什么程度。通过标准是后续判定和批次比较的对照锚点。

如果稳定性属于本轮通过标准，还应确定哪些测试用例需要验证稳定性，以及需要达到什么程度的稳定；具体重复样例和运行次数按第 3 步确定。

## 2. 设计测试用例

完整读取 `项目全局/第2层-具体规则层/测试用例设计规则.md`，根据第 1 步确认的调试对象和本轮通过标准，识别需要验证的功能、判断路径、边界和禁止项，建立对应测试用例，并确认测试用例集合覆盖 Prompt 承担的主要功能。

本轮需要验证稳定性时，应在选择测试样例前，按测试用例设计规则将稳定性要求写入相关用例的通过标准。

测试用例统一维护在 `<调试目录>/测试资产/` 下的 Excel 测试资产工作簿中，不再使用 Markdown 文档作为正式测试用例交付物。文件名使用 `<调试对象>测试资产.xlsx`；一个工作簿可以对应一个 Prompt，也可以对应一组共享样例的相关 Prompt，但每行必须能明确识别所属 Prompt。

工作簿必须包含 `测试用例` Sheet，每行只记录一个测试用例。Sheet 字段、字段顺序、必填条件、格式、枚举和多条内容的填写方式统一遵循 `项目全局/第3层-任务流程层/prompt调试资产模板.md`。

### 2.1 通用功能

通用功能测试优先使用常规、完整、无歧义的代表性输入，确认输出能否被正常使用，以及基本边界是否稳定。

通用功能样例主要检查：

- 输出结构是否符合输出契约。
- 是否补充了输入中不存在的信息。
- 是否遵守任务的输入边界和职责边界。
- 必要字段和格式是否稳定，没有明显漏项或格式漂移。

### 2.2 Prompt 特定功能

特定功能测试用于验证 prompt 是否完成了自身承担的全部主要任务。应先根据任务目标和输出契约检查功能是否遗漏，再为每个功能选择能触发对应处理的代表性样例。

每个特定功能样例主要检查：

- 对应功能是否完成。
- 必要字段、关键判断和处理结果是否正确。
- 输出是否遗漏该功能应处理的输入内容。
- 是否提前完成了其他节点或任务负责的判断。

特定功能测试只要能证明功能及其关键判断路径可用，不要为同一处理逻辑下的每个取值重复设计样例。

### 2.3 边缘情况

边缘情况测试用于验证某个已定义功能在非常规条件下是否仍按要求处理。边缘情况不要按所有可能输入穷举，只选择会改变判断路径、处理方式或输出要求的代表性情况。

设计边缘情况前，先确认该输入是否会实际进入当前 prompt。如果该情形由程序校验、输入拼接或其他上游环节拦截，应从当前 prompt 测试用例中排除，并归入对应责任层的测试。

边缘情况可包括：

- prompt 条件分支对应的输入。
- 正常但非常见的长尾输入。
- 存在数据质量问题的输入。
- 空输入、字段缺失、格式错误或内容冲突等异常输入。

## 3. 建立具体测试样例池

测试样例应来自第2部分设计的测试用例。
每个测试样例都必须能挂到一个或多个测试用例，并写清它验证哪个测试目标和哪些检查点。
每个测试样例都应写清测试目的、关联测试用例、输入情形和预期检查点。输入情形可以是常规输入、条件分支、长尾输入、数据质量问题或异常输入。

样例池应优先用最少量的代表性样例覆盖全部测试用例。同一个输入能够稳定验证多个测试目标时，应让它关联多个测试用例，不为每个用例重复创建一份近似样例。

预期检查点用于判断样例输出是否可用，不要求写完整标准答案，但必须能被人工或评价 prompt 稳定核查。检查点应覆盖本样例真正要验证的关键字段、关键判断、格式要求、禁止输出项、条件分支触发结果或异常处理结果。

关联测试用例要求验证稳定性时，应选择能够触发对应功能和判断路径的代表性样例重复运行，并在 `预期检查点` 中把用例的稳定性通过标准落实为该输入下可核查的具体结果。

具体样例统一维护在同一测试资产工作簿的 `测试样例` Sheet 中，不再使用 Markdown 或 JSON 文件作为正式样例池交付物。共享输入被多个 Prompt 使用时，每个“样例与 Prompt 的组合”单独一行，避免把多个 Prompt 的测试目的和检查点塞入同一单元格。

测试资产工作簿必须包含 `测试样例` 和 `版本记录` Sheet。两个 Sheet 的字段、字段顺序、必填条件、格式和枚举统一遵循 `项目全局/第3层-任务流程层/prompt调试资产模板.md`。

`重复运行次数` 默认为 `1`；需要验证稳定性时，对应代表性样例填写大于 `1` 的次数，不另外新增稳定性标准。

## 4. 维护版本与已有资产

`测试用例版本` 和 `样例版本` 同样使用 `v主版本.次版本.修订版本`：测试目标、通过标准或覆盖范围变化时增加测试用例版本；输入数据、测试目的、预期检查点或重复运行次数变化时增加样例版本。只修改排版或修正不影响含义的文字时增加修订版本。

维护测试资产前，核对用户对被测 Prompt 的实际修改是否改变预期行为：

- 只修复 Prompt，使其更稳定地达到原通过标准时，测试用例和预期检查点保持不变。
- 职责边界、判断规则、条件分支、输出契约或预期行为发生变化时，更新受影响的测试用例和样例检查点，增加对应测试资产版本，并在 `版本记录` Sheet 留痕；被测 Prompt 的实际版本由用户提供或确认。

## 5. 交付测试资产

交付测试资产工作簿及本次新增、修改或停用的用例和样例说明。核对用例与样例的关联、适用 Prompt 版本、通过标准、预期检查点和重复运行次数是否一致，并说明尚未覆盖的范围或待人工明确的要求。
